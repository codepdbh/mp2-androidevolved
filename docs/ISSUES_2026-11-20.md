## Validación reproducible

- `python -m unittest discover -s tests -p test_guest_alignment.py` comprueba el parche x87, su idempotencia
  y que las huellas de la validación Java coincidan con los módulos recompilados.
- `python -m unittest discover -s tests -p test_android_issue_helpers.py` compila y ejecuta las pruebas Java con un JDK local.
- `tests/java/com/mp2r/android/IssueFixesTest.java` verifica huellas, datos ausentes, versiones incompatibles,
  preservación del INI, claves vacías/ausentes, configuración regional y selección del error entre avisos del fabricante.
  Se compila con las clases puras `GameDataCheck`, `WidescreenConfig` y `ReportExcerpt`.
- `tests/frame_rate_test.cpp` comprueba 60/30 FPS, ausencia de muestras y reinicio después de pausas.
- `tests/guest_alignment_probe.c`, compilado con Clang del NDK para ARMv7, permite inspeccionar los accesos no alineados.

La unidad ARM32 real `rlmfc_recomp_0000.c` también se compiló con la corrección: en `sub_007F36D0`,
el acceso a `+0x5f3` genera `vst1.8 {d0}, [r0]`. Compilan igualmente `main.cpp`, `guest_runtime.cpp`
y `d3d8_bridge.cpp` para ARM32. No se debe reutilizar la biblioteca ARM32 de 0.22: para distribuir esta
corrección hay que recompilarla; cambiar únicamente Java no corrige el SIGBUS.

No había dispositivos disponibles en ADB durante esta revisión. Las pruebas locales no sustituyen
las comprobaciones en los modelos de los reportes.

Resultado local: tres tests Python de alineación/huellas, la suite de regresión Java y seis tests
C++ pasan. La APK ARM64 de depuración se compiló e inspeccionó después de los últimos cambios:
firma v2 válida, biblioteca ARM64 con segmentos alineados a 16 KiB, clases nuevas y JNI del contador
presentes. No contiene archivos `.ras`, `.exe` ni `.asi`. La comprobación ARM32 cubre las unidades
modificadas y `rlmfc`; no es una APK ARM32 completa ni una prueba en dispositivo.

## Publicación 0.23-pc — 26 de noviembre de 2026

La preparación de 0.23-pc completa la compilación Release de ARM64 y ARM32 y la verificación de
las dos APK firmadas. ARM32 se reconstruye con la corrección nativa: se comprobaron las 214 copias
generadas y el acceso a `+0x5f3` de `rlmfc`, que utiliza `vst1.8`. Se mantienen la firma de 0.22 y
los requisitos de datos descritos en el README.

También se incluyen controles de golpe, agacharse, Enter, guardado rápido F5 y carga rápida F9,
con el mapeo de F1–F10 en los mensajes del runtime. Estas APK no se han probado en un teléfono;
ARM32 continúa siendo experimental y los reportes específicos de dispositivos siguen pendientes
de confirmación. La validación de publicación no sustituye esas pruebas.
